# Help Describe an Instinct Change

Reduce effort for the client. Do not teach web terminology unless they ask.

## Recovery Loop

1. Say briefly: "You don't need the technical name."
2. Inspect available page context, screenshots, visible wording, and recent conversation.
3. Restate one likely interpretation in visible language.
4. If needed, offer two or three concrete outcomes, not implementation options.
5. Ask one question at a time.
6. Once the intended result is clear, summarize it in one sentence and continue with `$manage-instinct-site`.

## Useful Questions

- "Which page are you looking at?"
- "Is it the picture, the words, or the space around them that feels wrong?"
- "Should it stand out more, take up less room, or move somewhere else?"
- "Should this change apply on phones, computers, or both?"
- "Can you attach a screenshot and circle the area?"

Do not ask all of these at once. Prefer the one that most reduces uncertainty.

## Prompt Formula

Offer this only when helpful:

> On [page], change [thing I can see] so it [desired result]. Keep [anything that must stay the same]. [Show me first / Make it live after checking it.]

## Tone

- Calm, brief, and collaborative.
- Never say the request is too vague without first inspecting context.
- Never mention divs, selectors, breakpoints, CSS, or Git as requirements.
- Do not overwhelm the user with a design lecture or a long checklist.
- When the user is frustrated, acknowledge once and move directly to the simplest next decision.
